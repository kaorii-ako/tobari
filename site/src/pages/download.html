01 · Verify

How a release will be verified

Every release will be signed with minisign. No release key exists yet. These steps are here so you can check the process before there is anything to check.

  1. Get the public key from two places

    The key will be committed to the repository root as tobari.pub and published on this site, so one copy can be checked against the other. Neither exists yet, and nothing should be described as signed until one does.

    Public key
    not yet published
    Repository
    tobari.pub · not yet published
    This site
    /tobari.pub · not yet published

  2. Download the release files

    From GitHub Releases: the Flatpak bundle tobari.flatpak, the tarball tobari-<version>-linux-x86_64.tar.gz, plus SHA256SUMS and SHA256SUMS.minisig. One signature covers the checksum file, and the checksum file covers every artifact.

  3. Check the signature, then the checksums

    minisign -Vm SHA256SUMS -p tobari.pub && sha256sum -c SHA256SUMS

    If minisign does not report the signature as verified, the download is not Tobari. Stop, and open an issue.

    The secret key is kept offline. If Tobari later ships on Flathub, which needs a manifest that builds from source, those builds carry Flathub's signature, not this key. RELEASING § Signing

02 · Linux

Build from source

Every build tool lives in a distrobox container; nothing is layered onto the host. The steps follow DEV-LINUX.

  1. Create the container and install the toolchain

    distrobox create --name tobari --image registry.fedoraproject.org/fedora:41
distrobox enter tobari
sudo dnf install -y git cmake ninja-build gcc-c++ python3 python3-pillow openssl \
  gtk3-devel libX11-devel libXi-devel nss-devel alsa-lib-devel \
  at-spi2-atk-devel cups-devel libdrm-devel mesa-libgbm-devel
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y

    All later steps run inside it. Rust is needed because the blocking engine is a Rust library that CMake builds with Cargo.

  2. Clone the repository

    git clone https://github.com/kaorii-ako/tobari
cd tobari

  3. Provision CEF

    CEF_ROOT=$(shell/provision-cef.sh | tail -1)

    shell/provision-cef.sh downloads the pinned CEF build ({{cef_version}}, minimal distribution), checks it against the SHA-1 pinned in the script, and unpacks it into ~/.cache/tobari-dev/. It prints the CEF root as its last line, and a second run reuses the verified copy.

  4. Configure and build

    cmake -S shell -B ~/.cache/tobari-dev/build -G Ninja \
  -DCEF_ROOT="$CEF_ROOT" -DCMAKE_BUILD_TYPE=Release
cmake --build ~/.cache/tobari-dev/build

    One build produces everything: the Rust blocking engine (Cargo is driven from CMake), the tobari binary, the two bundled extensions and the filter lists staged beside it.

  5. Run it

    ~/.cache/tobari-dev/build/tobari

    XDG_DATA_HOME=/tmp/p gives a throwaway profile; TOBARI_NO_BLOCKING=1 starts it without the blocking engine; TOBARI_LOG=info raises log verbosity.

03 · Install

Install your build

Both formats keep Chromium's sandbox on. Neither ever passes --no-sandbox. PACKAGING

  1. Flatpak (primary)

    packaging/flatpak/build.sh ~/.cache/tobari-dev/build --install
flatpak run dev.tobari.Browser

    Renderers are sandboxed through Flatpak's own sandbox via zypak, as in Chromium's Flatpak. The profile lives under ~/.var/app/dev.tobari.Browser/. It packages a build made outside flatpak-builder, so it is not yet ready for Flathub.

  2. Per-user install

    packaging/install.sh ~/.cache/tobari-dev/build               # install
packaging/install.sh ~/.cache/tobari-dev/build --set-default # and make it the default browser
packaging/install.sh --uninstall

    Installs into ~/.local and writes nothing outside your home directory, so it works on immutable distributions. It depends on unprivileged user namespaces for the sandbox and refuses to install if they are disabled. Installing never changes your default browser unless you pass --set-default.
