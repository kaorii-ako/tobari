01 · Verify

How a release will be verified

Every release will be signed with minisign. These steps are here so you can check the process before there is anything to check.

  1. Get the public key from two places

    The key will be committed to the repository root as tobari-release.pub and published on this site, so one copy can be checked against the other. Neither exists yet.

    Public key
    not yet published
    Repository
    tobari-release.pub · not yet published
    This site
    /tobari-release.pub · not yet published

  2. Download the release files

    From GitHub Releases: the build, plus SHA256SUMS and SHA256SUMS.minisig. One signature covers the checksum file, and the checksum file covers every artifact.

  3. Check the signature, then the checksums

    minisign -Vm SHA256SUMS -P <public key, not yet published>
sha256sum -c SHA256SUMS --ignore-missing

    minisign -V must print Signature and comment signature verified. If it does not, the download is not Tobari. Stop, and open an issue.

    Signing happens on the developer's machine, not in CI, so a compromised workflow cannot produce a signed build. If Tobari later ships on Flathub, those builds carry Flathub's signature, not this key. RELEASING § Signing key

02 · Linux

Build from source

Everything happens inside a distrobox container; nothing is installed on the host. The steps follow shell/CMakeLists.txt and the CEF provisioning script in the repository.

  1. Create and enter the container

    distrobox create --name tobari --image registry.fedoraproject.org/fedora:41
distrobox enter tobari

    All later steps run inside it. On an atomic system such as Bazzite, never layer build tools onto the host.

  2. Install the toolchain

    sudo dnf install -y git curl cmake ninja-build gcc-c++ python3 bzip2
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source "$HOME/.cargo/env"

    Rust is needed because the blocking engine is a Rust library that CMake builds with Cargo.

  3. Clone the repository

    git clone https://github.com/kaorii-ako/tobari
cd tobari

  4. Provision CEF

    export CEF_ROOT="$(shell/provision-cef.sh | tail -n 1)"

    shell/provision-cef.sh downloads the pinned CEF build (154.0.32+g682c378+chromium-154.0.8037.58, minimal distribution) from the CEF build index, checks it against the SHA-1 published in that index, refuses it on a mismatch, and unpacks it into ~/.cache/tobari-dev/. It prints the CEF root as its last line, and a second run reuses the verified copy. CMake stops with an error if CEF_ROOT is not set.

  5. Configure and build

    cmake -S shell -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build

    One build produces everything: CMake drives Cargo for the adblock-rust library and links it into the browser.

  6. Run it

    ./build/tobari

    TOBARI_NO_BLOCKING=1 starts it without the blocking engine; TOBARI_LOG=info raises log verbosity. The container and toolchain are described in more detail in DEV-LINUX.

03 · Elsewhere

Other platforms

macOS
Build from source only
A .dmg that people can open needs notarization, which needs a paid Apple Developer account. There is no such account and no Mac to test on, so an unnotarized .dmg would be blocked by Gatekeeper on first launch. None will be published until both exist. The build has not been run on a Mac. Windows
Not supported
