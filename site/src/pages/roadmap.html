Roadmap

Browser first.

No dates. Each step starts when the one before it is done.

  1. Now

    Phase 1: the browser

    Works end to end and is packaged: Chromium's own window on CEF, Chrome extensions from the Web Store, network-layer blocking with a toolbar switch, a Flatpak and a per-user install. Still to do before this step is finished: a week of daily-driver use on Wayland, the from-source Flatpak manifest Flathub requires, and a published release with a signing key.

    Phase 1 was built under a waiver: VALIDATION still records no go, pivot or stop decision, and the waiver does not extend to Phase 2.

  2. Always

    Engine currency

    Ship each CEF build that carries a Chromium security fix within 3 days of it appearing, and record every gap. RELEASING § The CEF bump

  3. Only if needed

    Phase 2: a Chromium patch set

    Starts only if a measurement shows a specific, named limit CEF cannot get past. Memory does not show one. The engine-currency gap is the stronger argument for owning a Chromium build, at the cost of a 4–8 hour build and a rebase every four weeks, indefinitely; it is recorded as the open question, not decided. BENCHMARKS § Decision on Phase 2

  4. Later

    Phase 3: a local assistant

    An assistant that runs only on your machine through llama.cpp, with no cloud path of any kind. Its threat model will be documented before it ships. It is not in this build. SECURITY § Planned
